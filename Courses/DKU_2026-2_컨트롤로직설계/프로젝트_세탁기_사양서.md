# 컨트롤로직 설계 — 학기 프로젝트 주제별 사양서: 세탁기

### 2코스 세탁기 제어기

> 이 문서는 학기 프로젝트 **세탁기 주제**의 필수 기능, 핵심 연산, 지정 시나리오를 정한 사양서입니다.
>
> 설계 절차, 공통 요구 사항, 제출물, 평가 기준은 [공통 사양서](프로젝트_공통_사양서.md)에서 정합니다. 두 문서를 함께 확인하십시오.

---

## 1. 주제 개요

| 항목 | 내용 |
|------|------|
| 설계 대상 | 코스 2종(표준, 강력)의 세탁기 제어기 |
| 제어하는 동작 | 세탁, 헹굼, 탈수 단계를 시간에 따라 진행하고, 문이 열리면 일시 정지 |
| 핵심 반복 연산 | 전체 시간(세탁 + 헹굼 × 횟수 + 탈수)을 가산기 1개로 누적해 계산 |
| 클럭 수 요구 | 전체 시간 계산 = 정확히 (2 + 헹굼 횟수)클럭<br>세탁부터 탈수 완료까지 = 정확히 전체 시간만큼의 클럭 |

---

## 2. 입출력 정의

| 구분 | 신호 | 비트 | 의미 |
|------|------|:--:|------|
| 입력 | `START` | 1 | 시작 버튼. 누르는 동안 1 |
| 입력 | `COURSE` | 1 | 코스 선택 스위치. 0이면 표준, 1이면 강력 |
| 입력 | `DOOR` | 1 | 문 센서. 문이 열려 있는 동안 1 |
| 입력 | `RESET` | 1 | 리셋 |
| 출력 | `TIME` | 5 | 전체 남은 시간 표시 |
| 출력 | `CALC` | 1 | 전체 시간을 계산하는 중이면 1 |
| 출력 | `WASH`, `RINSE`, `SPIN` | 각 1 | 현재 단계 표시. 차례로 세탁, 헹굼, 탈수 |

- 클럭 입력은 따로 둡니다.
- 시간의 단위는 클럭입니다. 세탁 5는 세탁을 5클럭 동안 진행한다는 뜻입니다.

---

## 3. 기능 정의

1. **시작과 코스 저장** — 대기 중에 시작 버튼을 누르면 그 클럭의 `COURSE` 값을 저장하고 동작을 시작합니다.
2. **전체 시간 계산** — 시작하면 먼저 저장한 코스의 전체 시간을 계산해 남은 시간 레지스터에 저장합니다. 계산하는 동안 `CALC`가 1입니다.
3. **단계 진행** — 계산을 마치면 세탁, 헹굼, 탈수 순서로 진행합니다. 헹굼은 헹굼 횟수만큼 반복합니다. 진행 중인 단계의 표시가 1이고, 한 클럭을 진행할 때마다 `TIME`이 1씩 감소합니다.
4. **일시 정지와 재개** — 진행 중에 문이 열리면 정지합니다. 문이 닫히면 정지한 지점부터 이어서 진행합니다.
5. **완료** — 탈수를 마치면 대기 상태로 돌아갑니다.

**코스별 단계 시간**

| 코스 | 세탁 | 헹굼 1회 | 헹굼 횟수 | 탈수 | 전체 시간 |
|------|:--:|:--:|:--:|:--:|:--:|
| 표준 | 5 | 3 | 2 | 4 | 15 |
| 강력 | 8 | 4 | 3 | 6 | 26 |

---

## 4. 핵심 연산과 클럭 수

### 4.1 핵심 반복 연산

- 전체 시간은 **세탁 시간 + 헹굼 시간 × 헹굼 횟수 + 탈수 시간**입니다. 시작 버튼을 접수하면 이 값을 계산해 남은 시간 레지스터에 저장합니다.
- **가산기 1개**를 한 클럭에 한 번 사용해 단계 시간을 하나씩 누적하십시오. 헹굼 시간은 헹굼 횟수만큼 반복해 더합니다.
- 단계 시간과 헹굼 횟수는 **ROM**에 저장하십시오. 전체 시간(15, 26)을 ROM에 저장해 두는 구현은 인정하지 않습니다.
- 반복의 종료는 데이터패스의 상태 신호(반복 횟수의 일치 여부, 마지막 단계 여부)로 판단합니다.

**ROM에 저장할 값 (권장 배치)**

| 주소 | 코스 | 단계 | 단계 시간 | 반복 횟수 |
|:--:|------|------|:--:|:--:|
| 0 | 표준 | 세탁 | 5 | 1 |
| 1 | 표준 | 헹굼 | 3 | 2 |
| 2 | 표준 | 탈수 | 4 | 1 |
| 4 | 강력 | 세탁 | 8 | 1 |
| 5 | 강력 | 헹굼 | 4 | 3 |
| 6 | 강력 | 탈수 | 6 | 1 |

- 주소의 최상위 비트는 저장한 코스이고, 아래 2비트는 단계 번호(0 세탁, 1 헹굼, 2 탈수)입니다. 주소 3과 7은 사용하지 않습니다.
- 한 워드에 단계 시간(4비트)과 반복 횟수(2비트)를 함께 저장한 배치입니다. 한 클럭에 ROM을 한 번 읽어 두 값을 함께 얻습니다.
- 값은 그대로 두고 주소 순서와 워드 구성은 바꾸어도 됩니다. 바꾼 경우에는 ROM의 내용을 보고서 4절에 표로 적으십시오.

### 4.2 정확한 클럭 수

| 동작 | 요구 |
|------|------|
| 전체 시간 계산 | `CALC`가 **정확히 (2 + 헹굼 횟수)클럭 동안 연속으로** 1<br>표준 4클럭, 강력 5클럭 |
| 세탁부터 탈수 완료까지 | 단계 표시가 1이고 `DOOR`가 0인 클럭이 **정확히 전체 시간만큼**<br>표준 15클럭, 강력 26클럭 |
| 단계별 클럭 수 | `DOOR`가 1인 클럭을 제외하고 `WASH`, `RINSE`, `SPIN`이 1인 클럭 수가 각각 세탁 시간, 헹굼 시간 × 헹굼 횟수, 탈수 시간과 같음 |
| 단계 사이 | 계산과 세탁 사이, 단계와 단계 사이에 `CALC`와 단계 표시가 모두 0인 클럭이 없음 |
| 남은 시간 | 계산을 마친 다음 클럭에 `TIME` = 전체 시간<br>한 클럭을 진행할 때마다 1씩 감소<br>탈수의 마지막 클럭에 1, 그다음 클럭에 0 |

- `DOOR`가 1인 클럭은 진행한 클럭으로 계수하지 않습니다.
- `DOOR`가 0인 클럭에는 반드시 한 클럭을 진행해야 합니다. 문이 닫힌 뒤 재개를 준비하는 클럭을 두면 「정확히」 요구를 충족하지 못합니다.
- 계산하는 동안의 `TIME` 값은 평가하지 않습니다. 누적 중인 값을 표시해도 됩니다.

### 4.3 처리 방식의 정의

| 상황 | 처리 |
|------|------|
| 리셋 직후 | 대기 상태, `TIME` = 0, `CALC`와 단계 표시는 모두 0 |
| 시작 버튼과 `COURSE`가 같은 클럭에 바뀜 | 바뀐 뒤의 `COURSE` 값을 저장 |
| 문이 열린 상태에서 누른 시작 버튼 | 접수<br>계산은 그대로 진행<br>계산을 마치면 세탁의 첫 클럭에서 일시 정지한 것으로 처리(`WASH` = 1, `TIME` = 전체 시간) |
| 계산 중의 문 열림 | 계산을 멈추지 않음 |
| 진행 중의 문 열림 | `DOOR`가 1인 클럭에는 진행하지 않음<br>단계 표시와 `TIME`은 그대로 유지 |
| 단계의 마지막 클럭에 문이 열림 | 그 클럭은 진행한 클럭이 아님<br>문이 닫힌 뒤 그 단계의 남은 1클럭을 진행하고 다음 단계로 이동 |
| 계산 중, 진행 중, 일시 정지 중에 누른 시작 버튼 | 무시<br>완료된 뒤까지 누르고 있어도 새로 시작하지 않음 |
| 계산 중, 진행 중, 일시 정지 중의 `COURSE` 변경 | 무시<br>저장한 코스로 완료까지 진행 |
| 완료 | 탈수의 마지막 클럭 다음 클럭에 대기 상태<br>단계 표시는 모두 0 |

- 시작 버튼을 접수한 뒤 계산을 시작하기까지의 클럭 수는 설계에 따라 다를 수 있습니다. 평가는 4.2의 요구와 이 표의 처리를 기준으로 합니다.

## 5. 지정 시나리오

- 클럭 번호는 리셋을 해제한 뒤의 첫 클럭을 1번으로 합니다.
- 입력열에 적지 않은 클럭에서 입력은 모두 0입니다. `COURSE`가 0이면 표준 코스, `DOOR`가 0이면 문이 닫힌 상태입니다.
- 시나리오마다 리셋 직후의 상태에서 시작하십시오.

| # | 종류 | 입력열 | 추적할 클럭 | 확인 사항 |
|:--:|------|------|:--:|------|
| 1 | 정상 동작 1 | `START` = 클럭 2\~3 | 1\~24 | 표준 코스<br>`CALC` 4클럭 연속<br>세탁 5, 헹굼 6, 탈수 4클럭을 빈 클럭 없이 진행<br>`TIME`이 15에서 0까지 감소<br>이후 대기 |
| 2 | 정상 동작 2 | `COURSE` = 클럭 1\~40<br>`START` = 클럭 2\~3<br>`DOOR` = 클럭 10\~12 | 1\~40 | 강력 코스<br>`CALC` 5클럭 연속<br>세탁 중에 3클럭 동안 일시 정지하고, 정지한 지점에서 재개<br>`DOOR`가 1인 클럭을 제외하고 세탁 8, 헹굼 12, 탈수 6클럭 |
| 3 | 길게 누름 | `START` = 클럭 2\~30 | 1\~34 | 표준 코스를 한 번만 진행<br>완료된 뒤에 `START`가 1이어도 다시 시작하지 않음 |
| 4 | 동시 입력 | `START` = 클럭 2\~3<br>`COURSE` = 클럭 2\~5<br>`DOOR` = 클럭 2\~9 | 1\~38 | 시작 버튼, 코스 변경, 문 열림이 같은 클럭에 주어짐<br>강력 코스로 접수<br>문이 열려 있어도 `CALC` 5클럭 연속<br>세탁은 문이 닫힌 클럭 10부터 진행<br>클럭 6에 `COURSE`가 0으로 바뀌어도 강력 코스 26클럭 진행 |
| 5 | 처리 중 입력 | `START` = 클럭 2\~3<br>`COURSE` = 클럭 8\~14<br>`DOOR` = 클럭 11\~13<br>`START` = 클럭 12\~13<br>`DOOR` = 클럭 18\~19 | 1\~30 | 진행 중의 코스 변경과 일시 정지 중의 시작 버튼은 무시<br>단계의 마지막 클럭에 문이 열림<br>문이 닫힌 뒤 남은 1클럭을 진행하고 다음 단계로 이동<br>`DOOR`가 1인 클럭을 제외하고 세탁 5, 헹굼 6, 탈수 4클럭 |

- 시나리오마다 공통 사양서 5.1의 형식으로 추적 표를 작성하고, Logisim 결과와 대조하십시오.
- 추적 표의 「레지스터와 카운터의 값」에는 남은 시간, 저장한 코스, 현재 단계를 나타내는 값, 단계 타이머 값, 헹굼 횟수 카운터 값을 포함하십시오.
- 시나리오 5의 `DOOR` 구간은 단계의 마지막 클럭에 문이 열리도록 정했습니다. 계산을 클럭 3에 시작하는 설계에서는 클럭 11이 세탁의 마지막 클럭이고, 계산을 클럭 4에 시작하는 설계에서는 클럭 18이 첫 번째 헹굼의 마지막 클럭입니다.
- 본인 설계에서 두 구간이 모두 단계의 마지막 클럭에 해당하지 않으면, 첫 번째 `DOOR` 구간이 세탁의 마지막 클럭에서 시작하도록 옮긴 추적 표를 하나 추가하고, 옮긴 클럭 수를 적으십시오.

## 6. 변형 질문

1. 강력 코스의 헹굼 횟수를 3회에서 **4회**로 바꾸려면 설계의 어디를 어떻게 고쳐야 합니까. 고친 뒤 강력 코스의 전체 시간 계산과 단계 진행은 각각 몇 클럭입니까. 비트 수를 늘려야 하는 부품과 늘리지 않아도 되는 부품을 구분해 적으십시오.
2. 탈수를 마친 뒤 **문을 열 때까지 완료 표시(`DONE`)를 1로 유지**하도록 바꾸려면 설계의 어디를 어떻게 고쳐야 합니까. 탈수의 마지막 클럭에 문이 열렸다가 닫힌 경우, 완료 표시는 언제 1이 되고 언제 0이 됩니까.

## 7. 유의 사항

- 설계 절차, 입력 조건(한 번 누름의 한 번 처리), 리셋, 비정상 상태 추적, 제출물, 평가 기준은 [공통 사양서](프로젝트_공통_사양서.md)를 따릅니다.
- 단계 시간, 헹굼 횟수, 클럭 수, 처리 방식은 이 문서의 값을 그대로 사용하십시오. 임의로 바꾸면 지정 시나리오로 검증할 수 없습니다.
