# 컨트롤로직 설계 — 학기 프로젝트 주제별 사양서: 디지털 시계

### 알람과 다시 울림 기능이 있는 디지털 시계 제어기

> 이 문서는 학기 프로젝트 **디지털 시계 주제**의 필수 기능, 핵심 연산, 지정 시나리오를 정한 사양서입니다.
>
> 설계 절차, 공통 요구 사항, 제출물, 평가 기준은 [공통 사양서](프로젝트_공통_사양서.md)에서 정합니다. 두 문서를 함께 확인하십시오.

---

## 1. 주제 개요

| 항목 | 내용 |
|------|------|
| 설계 대상 | 시와 분을 표시하고 알람 기능이 있는 디지털 시계 제어기 |
| 제어하는 동작 | 분 펄스로 시각을 계수하고, 알람 시각과 같아지면 울림 |
| 핵심 반복 연산 | 다시 울림 버튼을 누르면 알람 시각에 「1분 더하기」를 5회 반복 |
| 클럭 수 요구 | 다시 울림의 더하기 = 정확히 5클럭 |

---

## 2. 입출력 정의

| 구분 | 신호 | 비트 | 의미 |
|------|------|:--:|------|
| 입력 | `TICK` | 1 | 분 펄스. 1분마다 1클럭 동안 1 |
| 입력 | `MODE` | 1 | 모드 스위치. 0이면 시각 설정, 1이면 알람 설정 |
| 입력 | `AL_ON` | 1 | 알람 사용 스위치. 1이면 알람 사용 |
| 입력 | `BH`, `BM` | 각 1 | 시 증가 버튼, 분 증가 버튼. 누르는 동안 1 |
| 입력 | `SNZ` | 1 | 다시 울림 버튼. 누르는 동안 1 |
| 입력 | `STOP` | 1 | 정지 버튼. 누르는 동안 1 |
| 입력 | `RESET` | 1 | 리셋 |
| 출력 | `H`, `M` | 5, 6 | 현재 시각의 시(0\~23)와 분(0\~59) |
| 출력 | `AH`, `AM` | 5, 6 | 알람 시각의 시(0\~23)와 분(0\~59) |
| 출력 | `RING` | 1 | 알람이 울리는 동안 1 |

- 클럭 입력은 따로 둡니다.
- 초는 다루지 않습니다. 시와 분은 2진 값으로 출력하며, 10진 표시로 바꾸는 회로는 요구하지 않습니다.
- `TICK`은 1클럭 동안만 1이고, 연속한 두 클럭에 주어지지 않습니다. 공통 사양서 4.3의 「2클럭 이상 유지」는 버튼 4개(`BH`, `BM`, `SNZ`, `STOP`)에 적용합니다.
- `MODE`와 `AL_ON`은 값이 유지되는 스위치입니다. 지정 시나리오에서는 버튼을 누르는 동안과 그 앞뒤 2클럭 동안 스위치 값이 바뀌지 않습니다.

## 3. 기능 정의

1. **시각 계수** — `TICK`이 1인 클럭마다 현재 시각을 1분 증가시킵니다. 분이 59에서 0이 되면 시가 1 증가하고, 시는 23 다음에 0이 됩니다.
2. **시각 설정** — `MODE`가 0일 때 `BH`를 누르면 현재 시각의 시가 1 증가하고, `BM`을 누르면 분이 1 증가합니다.
3. **알람 설정** — `MODE`가 1일 때 `BH`와 `BM`은 현재 시각이 아니라 알람 시각을 증가시킵니다.
4. **울림과 정지** — `AL_ON`이 1이고 현재 시각이 알람 시각과 같아지면 `RING`이 1이 됩니다. `STOP`을 누르면 `RING`이 0이 됩니다.
5. **다시 울림** — 울리는 중에 `SNZ`를 누르면 `RING`이 0이 되고 알람 시각이 5분 뒤로 바뀝니다. 현재 시각이 바뀐 알람 시각과 같아지면 다시 울립니다.
6. **원래 알람 시각의 보존** — 다시 울림으로 바뀌기 전의 알람 시각을 따로 저장합니다. `STOP`을 누르면 알람 시각을 원래 값으로 되돌립니다.

---

## 4. 핵심 연산과 클럭 수

### 4.1 핵심 반복 연산

- 다시 울림은 알람 시각에 **「1분 더하기」를 5회 반복**해 구현하십시오. 한 클럭에 1분만 더합니다.
- 5를 한 번에 더하는 구현은 인정하지 않습니다.
- 더할 때마다 분 59 → 0의 자리올림과 시 23 → 0을 처리합니다. 예: 알람 시각 23:57에 5회 더하면 00:02입니다.
- 반복 횟수는 **횟수 카운터**로 계수합니다. 반복의 종료는 횟수 카운터가 제어유닛에 전달하는 상태 신호로 판단합니다.
- 더하기를 반복하는 동안에도 현재 시각의 계수는 멈추지 않습니다.

### 4.2 정확한 클럭 수

| 동작 | 요구 |
|------|------|
| 다시 울림의 더하기 | 알람 시각이 **정확히 5클럭 동안 연속으로**, 클럭마다 1분씩 증가 |
| 더하기의 종료 | 5번째 증가의 다음 클럭에는 알람 시각이 증가하지 않음. 종료만 판단하는 클럭을 두지 않음 |
| 반복 중의 분 펄스 | 분 펄스를 놓치지 않고 현재 시각에 반영. 더하기는 멈추거나 늦어지지 않음 |

- 5클럭 사이에 알람 시각이 증가하지 않는 클럭이 있으면 「연속」 요구를 충족하지 못합니다. 예: 알람 시각 00:01에서 더하기를 시작하면 다음 5클럭 동안 00:02, 00:03, 00:04, 00:05, 00:06으로 바뀝니다.

### 4.3 처리 방식의 정의

| 상황 | 처리 |
|------|------|
| 리셋 직후 | 현재 시각 00:00, 알람 시각 00:00, `RING` = 0<br>두 시각이 같아도 울리지 않음 |
| 울림의 시작 | 분 펄스로 현재 시각이 증가해 알람 시각과 같아진 때<br>`AL_ON` = 1이고 `MODE` = 0이어야 함 |
| `MODE` = 1(알람 설정 중)이거나 `AL_ON` = 0 | 현재 시각과 알람 시각이 같아져도 울림을 시작하지 않음 |
| 분 증가 버튼으로 분이 59에서 0이 됨 | 시가 1 증가. 분 펄스에 의한 증가와 같은 동작(시각 설정과 알람 설정 모두) |
| 분 펄스와 시 증가 버튼 또는 분 증가 버튼이 같은 클럭(`MODE` = 0) | 두 증가를 모두 반영<br>분 펄스와 분 증가 버튼이면 분은 모두 2 증가<br>두 증가가 같은 클럭에 실행될 필요는 없음 |
| 울리지 않을 때 누른 `SNZ` | 무시 |
| 울리지 않을 때 누른 `STOP` | 알람 시각을 원래 값으로 되돌림 |
| 더하기 5클럭 동안 주어진 분 펄스 | 현재 시각에 반영 |
| 더하기 5클럭 동안 누르기 시작한 버튼 | 무시. 더하기가 완료된 뒤까지 누르고 있어도 처리하지 않음 |
| 더하기 5클럭 동안 알람 시각이 현재 시각과 같은 값을 지나감 | 울림을 시작하지 않음 |

- 정지 버튼과 다시 울림 버튼을 같은 클럭에 누르면 정지 버튼을 처리하고 다시 울림 버튼은 무시합니다. 시 증가 버튼과 분 증가 버튼을 같은 클럭에 누르면 시 증가 버튼을 처리하고 분 증가 버튼은 무시합니다.
- 시각 설정 버튼으로 현재 시각이 알람 시각과 같아진 때의 울림 여부, 울리는 중에 `AL_ON`을 0으로 바꾼 때의 동작은 설계자가 정하고 보고서 1절에 적으십시오.
- 버튼을 누른 뒤 처리되는 클럭, 현재 시각이 알람 시각과 같아진 뒤 `RING`이 1이 되는 클럭은 설계에 따라 1\~2클럭 다를 수 있습니다. 평가는 4.2의 요구와 이 표의 처리 결과를 기준으로 합니다.

## 5. 지정 시나리오

- 클럭 번호는 리셋을 해제한 뒤의 첫 클럭을 1번으로 합니다.
- 입력열에 적지 않은 클럭에서 `TICK`과 버튼은 모두 0입니다. `MODE`와 `AL_ON`은 입력열에 적은 클럭에서 1이고, 그 밖의 클럭에서 0입니다.
- 시나리오 1, 3, 4, 5는 리셋 직후의 상태에서 시작하십시오.
- 시나리오 2는 리셋한 뒤 **현재 시각 23:56, 알람 시각 23:57**(원래 알람 시각도 23:57)을 레지스터에 직접 입력한 상태에서 시작하십시오. 분 59 → 0과 시 23 → 0의 자리올림을 짧은 입력열로 확인하기 위한 시작 값입니다. Logisim에서는 Poke 도구로 레지스터나 카운터를 선택한 뒤 값을 입력할 수 있습니다. 값은 16진수로 입력합니다(시 23은 17, 분 56은 38, 분 57은 39).

| # | 종류 | 입력열 | 추적할 클럭 | 확인 사항 |
|:--:|------|------|:--:|------|
| 1 | 정상 동작 1 | `MODE` = 클럭 1\~5, 16\~26<br>`AL_ON` = 클럭 15\~44<br>`BM` = 클럭 2\~3, 22\~23<br>`BH` = 클럭 11\~12, 18\~19<br>`TICK` = 클럭 8, 30, 42<br>`STOP` = 클럭 36\~37 | 1\~44 | 리셋 직후 울리지 않음<br>클럭 8의 분 펄스로 00:01이 되어 알람 시각과 같아져도 `AL_ON` = 0이므로 울리지 않음<br>알람 설정 중에 알람 시각이 현재 시각과 같은 01:01이 되어도 울리지 않음<br>클럭 30의 분 펄스로 01:02가 되어 울림<br>`STOP` 뒤 `RING` = 0<br>클럭 42의 분 펄스 뒤 01:03, 울리지 않음 |
| 2 | 정상 동작 2 | 시작 값: 현재 시각 23:56, 알람 시각 23:57<br>`AL_ON` = 클럭 1\~46<br>`TICK` = 클럭 3, 16, 21, 26, 31, 36<br>`SNZ` = 클럭 8\~9<br>`STOP` = 클럭 42\~43 | 1\~46 | 23:57에 울림<br>더하기 정확히 5클럭, 알람 시각 23:57 → 00:02<br>현재 시각 23:59 → 00:00<br>00:02에 다시 울림<br>`STOP` 뒤 `RING` = 0, 알람 시각 23:57 |
| 3 | 길게 누름 | `AL_ON` = 클럭 1\~48<br>`MODE` = 클럭 1\~12<br>`BM` = 클럭 2\~9, 36\~43<br>`TICK` = 클럭 16, 40<br>`SNZ` = 클럭 21\~32 | 1\~48 | 알람 시각이 한 번만 증가해 00:01<br>00:01에 울림<br>더하기가 한 번만 5클럭(알람 시각 00:06)<br>`SNZ`를 계속 누르고 있어도 더하기를 다시 시작하지 않음<br>현재 시각은 `BM`으로 한 번, 클럭 40의 분 펄스로 한 번 증가해 00:03 |
| 4 | 동시 입력 | `AL_ON` = 클럭 1\~32<br>`MODE` = 클럭 1\~12<br>`BM` = 클럭 2\~3, 5\~6, 8\~9, 16\~17<br>`TICK` = 클럭 16, 22<br>`STOP` = 클럭 28\~29 | 1\~32 | 알람 시각 00:03<br>클럭 16에 분 펄스와 `BM`이 함께 주어짐<br>현재 시각이 2분 증가해 00:02<br>클럭 22의 분 펄스로 00:03이 되어 울림<br>`STOP` 뒤 `RING` = 0 |
| 5 | 처리 중 입력 | `AL_ON` = 클럭 1\~50<br>`MODE` = 클럭 1\~6<br>`BM` = 클럭 2\~3<br>`TICK` = 클럭 10, 18, 26, 31, 36, 41<br>`SNZ` = 클럭 15\~16<br>`STOP` = 클럭 19\~20, 47\~48 | 1\~50 | 00:01에 울림<br>더하기 5클럭 동안 주어진 클럭 18의 분 펄스를 반영(현재 시각 00:02)<br>더하기는 정확히 5클럭(알람 시각 00:06)<br>더하기 동안 누른 첫 번째 `STOP`은 무시<br>00:06에 다시 울림<br>두 번째 `STOP` 뒤 `RING` = 0, 알람 시각 00:01 |

- 시나리오마다 공통 사양서 5.1의 형식으로 추적 표를 작성하고, Logisim 결과와 대조하십시오.
- 추적 표의 「레지스터와 카운터의 값」에는 현재 시각, 알람 시각, 원래 알람 시각, 횟수 카운터 값을 포함하십시오.
- 시나리오 4에서 본인 설계가 `BM`을 처리하는 클럭이 16이 아니면, 클럭 16의 분 펄스를 그 클럭으로 옮긴 추적 표를 하나 더 작성하십시오. 어느 경우에도 현재 시각은 00:02가 되어야 합니다.
- 시나리오 5에서 본인 설계의 더하기 5클럭 안에 클럭 18과 클럭 19가 포함되지 않으면, 클럭 18의 분 펄스와 첫 번째 `STOP`을 더하기 5클럭 안으로 옮기고 그 사실을 추적 표에 적으십시오.

## 6. 변형 질문

1. 횟수 카운터에 적재하는 값을 본인 설계의 값에서 **1 작은 값**으로 바꾸면 더하기는 몇 회 실행됩니까. 또한 더하기를 5회에서 **10회**로 바꾸려면 설계의 어디를 어떻게 고쳐야 합니까. 고치지 않아도 되는 곳도 함께 적으십시오.
2. 더하기를 반복하는 도중에 `STOP`을 누르면 **반복을 중단하고 알람 시각을 원래 값으로 되돌리도록** 바꾸려면 설계의 어디를 어떻게 고쳐야 합니까. 3번째 더하기를 실행할 클럭에 `STOP`이 처리되면 더하기는 모두 몇 회 실행됩니까.

## 7. 유의 사항

- 설계 절차, 입력 조건(한 번 누름의 한 번 처리), 리셋, 비정상 상태 추적, 제출물, 평가 기준은 [공통 사양서](프로젝트_공통_사양서.md)를 따릅니다.
- 시와 분의 범위, 반복 횟수, 클럭 수, 처리 방식은 이 문서의 값을 그대로 사용하십시오. 임의로 바꾸면 지정 시나리오로 검증할 수 없습니다.
