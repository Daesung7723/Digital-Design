### 제어유닛과 데이터패스로 나누어 설계하는 제어기

> 이 문서는 **학기 프로젝트의 공통 요구 사항, 제출물, 평가 기준**을 정한 사양서입니다.

## 4. 공통 요구 사항

### 4.1 핵심 연산

- 주제별 사양서가 지정한 **반복 연산**을 구현하십시오.
- 반복 연산은 **연산 부품 1개를 여러 클럭에 걸쳐 사용**하는 구조로 구현합니다. 종료는 데이터패스가 제어유닛에 전달하는 **상태 신호**로 판단합니다.
- 조합회로로 한 번에 계산하는 구현은 인정하지 않습니다.

> 기준 예제는 13회차의 순차 이진 곱셈기입니다. 가산기 1개로 「더하고 시프트」를 반복하고, 카운터의 $Zero$ 신호로 종료합니다.

### 4.2 클럭 수

- 주제별 사양서가 지정한 동작은 **정확히 지정한 클럭 수**에 완료되어야 합니다.
- 종료만 판단하는 클럭이나 단계 사이의 빈 클럭을 두지 마십시오.

> **자주 하는 실수**
>
> 판단 박스는 클럭 에지 **직전**의 값을 검사합니다. 레지스터를 바꾸는 클럭에는 바뀐 값을 판단에 사용할 수 없습니다. 클럭 수가 1 어긋나는 설계는 대부분 이 점에서 발생합니다.

### 4.3 입력 조건

- 버튼과 센서 입력은 **2클럭 이상 1로 유지**됩니다. 지정 시나리오에서는 한 동작의 전체 시간보다 길게 유지되는 입력도 주어집니다.
- 한 번 누른 입력은 **한 번만 처리**해야 합니다. 누른 시간에 따라 처리 횟수가 달라지면 감점합니다.
- 두 입력이 같은 클럭에 주어질 때의 처리 순서는 주제별 사양서를 따릅니다.
- 다른 동작을 처리하는 중에 주어진 입력의 처리 방식은 주제별 사양서를 따릅니다.

**에지 검출 회로 (사용 가능)**

입력이 0에서 1로 바뀐 첫 클럭에만 1이 되는 신호를 만드는 회로입니다. 한 번 누름을 한 번만 처리할 때 사용할 수 있습니다.

- 구성: D 플립플롭 1개와 AND 게이트 1개
- 입력 $X$를 D 플립플롭에 저장한 값을 $X_d$라 하면, $X_p = X \cdot X_d'$

| 클럭 | 1 | 2 | 3 | 4 | 5 | 6 |
|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| $X$ | 0 | 1 | 1 | 1 | 0 | 0 |
| $X_d$ | 0 | 0 | 1 | 1 | 1 | 0 |
| $X_p$ | 0 | 1 | 0 | 0 | 0 | 0 |

### 4.4 리셋

- 리셋 입력을 두고, 리셋으로 초기 상태를 설정하십시오.
- 리셋 직후의 **상태, 모든 레지스터와 카운터의 값, 출력**을 보고서 1절에 명시하십시오.
- 제어유닛의 리셋은 데이터패스의 레지스터를 초기화하지 않습니다. 데이터패스 레지스터를 초기화하는 방법을 함께 적으십시오.

### 4.5 제어유닛

| 항목 | 조건 |
|------|------|
| 구성 | 다음 둘 가운데 하나로 구성하십시오. 두 방식 모두 13회차에서 다루는 절차를 따릅니다.<br>· **MUX 방식(권장)**: D 플립플롭, MUX, 디코더로 구성합니다. MUX 입력표로 다음 상태 논리를, 디코더 출력으로 제어 신호를 만듭니다.<br>· **게이트 방식**: D 플립플롭과 게이트로 구성합니다. D 입력식과 제어 신호식을 도출합니다. |
| 상태 할당 | 이진과 원핫 가운데 선택하고, 선택 근거를 1\~2문장으로 서술하십시오. MUX 방식은 이진 할당입니다. |
| 제어 신호 | 신호마다 유형(상태 박스의 신호인지, 조건부 박스의 신호인지)을 명세 표에 구분하십시오. |

**비정상 상태 추적 (필수)**

- 제어유닛 플립플롭에 정상 상태가 아닌 값 **2가지**를 주었을 때의 동작을, D 입력식(MUX 방식은 MUX 입력표)에 대입해 클럭 단위로 추적하십시오.
- 원핫 할당: 「1이 2개인 값」 1가지와 「모두 0」
- 이진 할당: 사용하지 않는 코드 2가지. 사용하지 않는 코드가 없으면 그 사실을 적으십시오.
- 추적 결과(정상 상태로 돌아오는지, 그동안 어떤 제어 신호가 출력되는지)를 서술하십시오. 복귀 회로를 추가할 필요는 없습니다.

### 4.6 데이터패스와 Logisim 구조

- 제어유닛과 데이터패스를 **각각 서브서킷**으로 구성하고, 최상위 회로에서 두 서브서킷을 연결하십시오.
- 데이터패스에는 Logisim 라이브러리 부품을 사용할 수 있습니다: 레지스터, 시프트 레지스터, 카운터, 가산기, 감산기, 비교기, MUX, 디코더, ROM
- 제어유닛을 MUX 방식으로 구성하면 제어유닛에도 MUX와 디코더 부품을 사용할 수 있습니다.
- 최상위 회로에는 입력 핀, 출력 핀, 클럭, 리셋을 두고 신호 이름을 표시하십시오.
- 상태와 주요 레지스터의 값을 관찰할 수 있도록 출력 핀이나 표시 부품을 배치하십시오.

## 5. 검증

### 5.1 지정 시나리오 5종

주제별 사양서가 시나리오 5종의 **입력열**(클럭 번호마다의 입력 값)을 제시합니다.

| # | 종류 | 확인하는 것 |
|:--:|------|------|
| 1 | 정상 동작 1 | 기본 기능 |
| 2 | 정상 동작 2 | 핵심 반복 연산과 「정확히 N클럭」 |
| 3 | 길게 누름 | 한 번 누름의 한 번 처리 |
| 4 | 동시 입력 | 같은 클럭에 주어진 입력의 처리 |
| 5 | 처리 중 입력 | 다른 동작을 처리하는 중에 주어진 입력의 처리 |

시나리오마다 아래 두 가지를 제출하십시오.

1. **클럭 단위 추적 표** — ASMD 차트와 식을 근거로 작성한 예상 동작
2. **Logisim 결과 캡처** — 같은 입력열을 준 결과. 추적 표와 대조해 일치 여부를 표시

**추적 표의 형식**

| 클럭 | 입력 | 상태 | 레지스터와 카운터의 값 | 1인 제어 신호 | 출력 |
|:--:|------|------|------|------|------|
| 1 | | | | | |
| 2 | | | | | |

- 한 행은 한 클럭입니다. 상태와 레지스터 값은 그 클럭 **동안**의 값(에지 직전의 값)을 적으십시오.
- 「정확히 N클럭」 요구가 있는 구간은 시작 클럭과 완료 클럭을 표에 표시하십시오.
- 추적 표와 Logisim 결과가 다르면 원인을 찾아 설계를 수정하십시오. 수정하지 못했다면 차이와 추정 원인을 적으십시오.

### 5.2 변형 질문

- 주제별 사양서가 **변형 질문 2문항**을 제시합니다. 값이나 조건 하나를 바꾸면 본인 설계의 어디를 어떻게 고쳐야 하는지 묻는 문항입니다.
- 답에는 고칠 곳(ASMD 차트의 상자, 식, 부품의 비트 수나 값)과 고치지 않아도 되는 곳을 구분해 적으십시오.
