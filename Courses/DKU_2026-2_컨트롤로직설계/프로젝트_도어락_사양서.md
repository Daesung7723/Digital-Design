# 컨트롤로직 설계 — 학기 프로젝트 주제별 사양서: 도어락

### 4자리 암호 도어락 제어기

> 이 문서는 학기 프로젝트 **도어락 주제**의 필수 기능, 핵심 연산, 지정 시나리오를 정한 사양서입니다.
>
> 설계 절차, 공통 요구 사항, 제출물, 평가 기준은 [공통 사양서](프로젝트_공통_사양서.md)에서 정합니다. 두 문서를 함께 확인하십시오.

---

## 1. 주제 개요

| 항목 | 내용 |
|------|------|
| 설계 대상 | 4자리 암호 도어락 제어기 |
| 제어하는 동작 | 입력한 4자리를 저장된 암호와 비교해 문을 열고, 실패가 이어지면 잠금 |
| 핵심 반복 연산 | 한 자리 비교(1클럭)를 불일치하는 자리가 나오거나 마지막 자리에 이를 때까지 반복 |
| 클럭 수 요구 | 첫 불일치가 j번째 자리이면 비교 = 정확히 j클럭<br>모두 일치하면 비교 = 정확히 4클럭<br>문 열림 = 정확히 4클럭<br>잠금 = 정확히 8, 16, 32, 64클럭 |

---

## 2. 입출력 정의

| 구분 | 신호 | 비트 | 의미 |
|------|------|:--:|------|
| 입력 | `KEY` | 1 | 숫자 키 입력 신호. 숫자 키를 누르는 동안 1 |
| 입력 | `NUM` | 4 | 누른 숫자 키의 값(0\~9). `KEY`가 1인 동안 값이 유지됨 |
| 입력 | `OK` | 1 | 확인 버튼. 누르는 동안 1 |
| 입력 | `RESET` | 1 | 리셋 |
| 출력 | `CMP` | 1 | 암호를 비교하는 중이면 1 |
| 출력 | `DOOR` | 1 | 문이 열려 있으면 1 |
| 출력 | `LOCK` | 1 | 잠금 중이면 1 |
| 출력 | `FAIL` | 2 | 연속 실패 횟수 표시(0\~3) |

- 클럭 입력은 따로 둡니다.
- 숫자 키는 한 번에 하나만 누릅니다. 숫자 키를 이어서 누를 때는 두 키 사이에 `KEY`가 0인 클럭이 1개 이상 있습니다.
- 암호를 바꾸는 기능은 없습니다.

---

## 3. 기능 정의

1. **숫자 입력** — 숫자 키를 누르면 `NUM`의 값을 한 자리 저장합니다. 누른 순서대로 4자리까지 저장하고, 5번째부터의 숫자 키는 무시합니다.
2. **비교** — 4자리를 저장한 뒤 확인 버튼을 누르면, 저장한 4자리를 ROM의 암호와 첫 자리부터 한 자리씩 비교합니다. 비교하는 동안 `CMP`가 1입니다.
3. **문 열림** — 4자리가 모두 일치하면 문을 엽니다. 문이 열린 동안 `DOOR`가 1이고, 실패 횟수는 0이 됩니다.
4. **실패** — 불일치하는 자리가 있으면 실패 1회입니다. 4자리 미만에서 확인 버튼을 눌러도 실패 1회로 처리합니다. 실패할 때마다 `FAIL`이 1 증가합니다.
5. **잠금** — 3회 연속 실패하면 잠급니다. 잠금 중에는 `LOCK`이 1입니다. 잠금이 종료되면 실패 횟수를 0부터 다시 계수합니다.
6. **잠금 시간** — 첫 잠금은 8클럭이고, 잠금이 되풀이될 때마다 2배가 됩니다. 상한은 64클럭입니다. 문을 열면 잠금 시간은 처음 값(8클럭)으로 돌아갑니다.
7. **대기** — 입력이 없으면 문을 닫은 상태로 다음 입력을 기다립니다.

## 4. 핵심 연산과 클럭 수

### 4.1 핵심 반복 연산

- 암호 4자리는 **ROM**에 저장하십시오. 이 프로젝트의 암호는 **2, 7, 4, 9**입니다. 주소 0에 첫 자리(2), 주소 3에 마지막 자리(9)를 저장합니다.
- 확인 버튼을 누르면 저장한 4자리를 암호와 **4비트 비교기 1개**로, 첫 자리부터 한 클럭에 한 자리씩 비교하십시오. 비교기 여러 개나 16비트 비교기로 4자리를 한 번에 비교하는 구현은 인정하지 않습니다.
- 불일치하는 자리가 나오면 그 클럭에서 비교를 마칩니다. 남은 자리는 비교하지 않습니다.
- 반복의 종료는 데이터패스의 상태 신호(비교한 자리의 일치 여부, 마지막 자리인지의 여부)로 판단합니다.

### 4.2 정확한 클럭 수

| 동작 | 요구 |
|------|------|
| 비교 | 첫 불일치가 j번째 자리이면 `CMP`가 **정확히 j클럭 동안 연속으로** 1<br>4자리가 모두 일치하면 `CMP`가 **정확히 4클럭 동안 연속으로** 1 |
| 문 열림 | `DOOR`가 **정확히 4클럭 동안 연속으로** 1 |
| 잠금 | `LOCK`이 **정확히 8, 16, 32, 64클럭 동안 연속으로** 1 (아래 표) |
| 비교와 문 열림 | 4자리가 모두 일치하면 `CMP`가 0이 되는 클럭에 `DOOR`가 1이 됨 |
| 비교, 문 열림, 잠금 | `CMP`, `DOOR`, `LOCK` 가운데 둘 이상이 같은 클럭에 함께 1이 되지 않음 |

| 잠금의 순서(리셋 뒤, 또는 문을 마지막으로 연 뒤) | 1번째 | 2번째 | 3번째 | 4번째 이후 |
|------|:--:|:--:|:--:|:--:|
| 잠금 시간 | 8클럭 | 16클럭 | 32클럭 | 64클럭 |

- 예: 2, 7, 5, 9를 입력하고 확인 버튼을 누르면 3번째 자리가 첫 불일치이므로 `CMP`는 3클럭 동안 연속으로 1입니다. 4번째 자리는 비교하지 않습니다.
- 4자리 미만에서 확인 버튼을 누르면 비교하지 않으므로 `CMP`는 1이 되지 않습니다.

### 4.3 처리 방식의 정의

| 상황 | 처리 |
|------|------|
| 리셋 직후 | 저장된 자리 없음, 실패 횟수 표시 0, 문 닫힘, 잠금 아님, 첫 잠금 시간 8클럭 |
| 4자리를 저장한 뒤에 누른 숫자 키 | 무시. 저장된 4자리는 바뀌지 않음 |
| 4자리 미만(0자리 포함)에서 누른 확인 버튼 | 비교하지 않고 실패 1회로 처리 |
| 확인 버튼을 처리한 뒤 | 결과와 관계없이 저장된 자리를 모두 지움. 다음 입력은 첫 자리부터 저장 |
| 3번째 연속 실패 | `FAIL`이 3이 되고 잠금 시작. 잠금이 종료되면 `FAIL`은 0 |
| 비교 중, 문이 열린 동안, 잠금 중에 누른 숫자 키와 확인 버튼 | 무시. 그 동작이 종료된 뒤까지 유지되어도 처리하지 않음 |
| 숫자 키와 확인 버튼을 같은 클럭에 누름 | 확인 버튼을 처리하고, 그 숫자 키는 무시 |

- 숫자가 저장되는 시점, `FAIL` 표시가 바뀌는 시점은 설계자가 정하고 보고서 1절에 적으십시오.
- 확인 버튼을 누른 뒤 비교나 실패 처리를 시작하기까지의 클럭 수는 설계에 따라 다를 수 있습니다. 평가는 4.2의 요구와 처리 결과를 기준으로 합니다.

## 5. 지정 시나리오

- 클럭 번호는 리셋을 해제한 뒤의 첫 클럭을 1번으로 합니다.
- 「숫자 2 = 클럭 2\~3」은 그 클럭 동안 `KEY`가 1이고 `NUM`이 2라는 뜻입니다. 숫자를 여러 개 적은 줄은 적은 순서대로 클럭 구간에 대응합니다.
- 「`OK` = 클럭 2\~3, 6\~7」은 두 구간에서 `OK`를 한 번씩, 모두 두 번 누른다는 뜻입니다.
- 입력열에 적지 않은 클럭에서 `KEY`, `NUM`, `OK`는 모두 0입니다.
- 시나리오마다 리셋 직후의 상태에서 시작하십시오.

| # | 종류 | 입력열 | 추적할 클럭 | 확인 사항 |
|:--:|------|------|:--:|------|
| 1 | 정상 동작 1 | 숫자 2, 7, 4, 9 = 클럭 2\~3, 6\~7, 10\~11, 14\~15<br>`OK` = 클럭 18\~19 | 1\~30 | 4자리 저장<br>`CMP` 4클럭 연속<br>이어서 `DOOR` 4클럭<br>`FAIL`은 0 유지 |
| 2 | 정상 동작 2 | 숫자 2, 7, 5, 9, 1 = 클럭 2\~3, 6\~7, 10\~11, 14\~15, 18\~19<br>`OK` = 클럭 22\~23<br>숫자 2, 7, 4, 9 = 클럭 30\~31, 34\~35, 38\~39, 42\~43<br>`OK` = 클럭 46\~47 | 1\~58 | 5번째로 누른 숫자 1은 무시<br>3번째 자리 불일치로 `CMP` 3클럭, `FAIL` 1<br>두 번째 입력에서 `CMP` 4클럭, `DOOR` 4클럭, `FAIL` 0 |
| 3 | 길게 누름 | 숫자 2 = 클럭 2\~8<br>숫자 7, 4, 9 = 클럭 11\~12, 15\~16, 19\~20<br>`OK` = 클럭 23\~38 | 1\~42 | 길게 누른 숫자 2는 한 자리로만 저장<br>`CMP` 4클럭, `DOOR`는 한 번만 4클럭<br>문이 닫힌 뒤에 `OK`가 유지되어도 다시 처리하지 않음(`FAIL` 0 유지) |
| 4 | 동시 입력 | 숫자 2, 7, 4 = 클럭 2\~3, 6\~7, 10\~11<br>숫자 9와 `OK` = 클럭 14\~15<br>`OK` = 클럭 28\~29 | 1\~40 | 4번째 숫자와 `OK`가 같은 클럭에 주어짐<br>확인 버튼을 처리하고 숫자 9는 무시<br>3자리에서 확인한 것이므로 실패 1회<br>두 번째 `OK`도 실패 1회(`FAIL` 2) |
| 5 | 처리 중 입력 | `OK` = 클럭 2\~3, 6\~7, 10\~11<br>`OK` = 클럭 14\~15<br>`OK` = 클럭 24\~25, 28\~29, 32\~33<br>숫자 5 = 클럭 44\~54<br>숫자 2, 7, 4, 9 = 클럭 58\~59, 62\~63, 66\~67, 70\~71<br>`OK` = 클럭 74\~75 | 1\~86 | 0자리 확인 3회로 `LOCK` 8클럭<br>잠금 중에 누른 `OK`는 무시<br>다시 3회 실패하면 `LOCK` 16클럭<br>잠금이 종료되는 클럭에 걸쳐 유지된 숫자 5는 무시<br>이어서 입력한 2, 7, 4, 9로 `CMP` 4클럭, `DOOR` 4클럭 |

- 시나리오마다 공통 사양서 5.1의 형식으로 추적 표를 작성하고, Logisim 결과와 대조하십시오.
- 추적 표의 「레지스터와 카운터의 값」에는 저장된 자리, 저장한 자릿수, 비교 중인 자리의 번호, 실패 횟수, 타이머 값, 다음 잠금 시간을 포함하십시오.

## 6. 변형 질문

1. 잠금 조건을 3회 연속 실패에서 **5회 연속 실패**로, 잠금 시간의 상한을 64클럭에서 **128클럭**으로 바꾸려면 설계의 어디를 어떻게 고쳐야 합니까. 고치지 않아도 되는 곳도 함께 적으십시오.
2. 불일치하는 자리가 나와도 비교를 중단하지 않고 **4자리를 마지막 자리까지 비교**한 뒤에 결과를 내도록 바꾸려면 설계의 어디를 어떻게 고쳐야 합니까. 바꾼 설계에서 첫 불일치가 1번째 자리이면 `CMP`는 몇 클럭 동안 1입니까.

## 7. 유의 사항

- 설계 절차, 입력 조건(한 번 누름의 한 번 처리), 리셋, 비정상 상태 추적, 제출물, 평가 기준은 [공통 사양서](프로젝트_공통_사양서.md)를 따릅니다.
- 암호, 자릿수, 클럭 수, 처리 방식은 이 문서의 값을 그대로 사용하십시오. 임의로 바꾸면 지정 시나리오로 검증할 수 없습니다.
