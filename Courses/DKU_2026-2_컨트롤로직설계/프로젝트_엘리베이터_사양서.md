# 컨트롤로직 설계 — 학기 프로젝트 주제별 사양서: 엘리베이터

### 4층 엘리베이터 제어기

> 이 문서는 학기 프로젝트 **엘리베이터 주제**의 필수 기능, 핵심 연산, 지정 시나리오를 정한 사양서입니다.
>
> 설계 절차, 공통 요구 사항, 제출물, 평가 기준은 [공통 사양서](프로젝트_공통_사양서.md)에서 정합니다. 두 문서를 함께 확인하십시오.

---

## 1. 주제 개요

| 항목 | 내용 |
|------|------|
| 설계 대상 | 4층 건물의 엘리베이터 제어기 |
| 제어하는 동작 | 층 요청에 따라 이동하고, 도착한 층에서 문을 여닫음 |
| 핵심 반복 연산 | 한 층 이동(3클럭)을 요청이 남아 있는 동안 반복 |
| 클럭 수 요구 | 멈추지 않고 n층 이동 = 정확히 3n클럭<br>문 열림 = 정확히 4클럭 |

---

## 2. 입출력 정의

| 구분 | 신호 | 비트 | 의미 |
|------|------|:--:|------|
| 입력 | `B1`, `B2`, `B3`, `B4` | 각 1 | 1\~4층의 층 요청 버튼. 누르는 동안 1 |
| 입력 | `RESET` | 1 | 리셋 |
| 출력 | `FLOOR` | 2 | 현재 층 표시 |
| 출력 | `DIR` | 1 | 진행 방향. 1이면 위, 0이면 아래 |
| 출력 | `MOVE` | 1 | 이동 중이면 1 |
| 출력 | `DOOR` | 1 | 문이 열려 있으면 1 |

- 클럭 입력은 따로 둡니다.
- 엘리베이터 안의 버튼과 층의 호출 버튼을 구분하지 않습니다. 층마다 버튼은 하나입니다.

---

## 3. 기능 정의

1. **요청 저장** — 버튼을 누르면 그 층의 요청을 저장합니다. 요청은 여러 층을 동시에 저장할 수 있어야 합니다. 같은 층의 버튼을 처리 전에 여러 번 눌러도 요청은 1건입니다.
2. **이동** — 저장된 요청이 있으면 그 층을 향해 한 층씩 이동합니다. 이동하는 동안 `MOVE`가 1입니다.
3. **정지와 문 열림** — 요청이 저장된 층에 도착하면 정지하고 문을 엽니다. 문이 열린 동안 `DOOR`가 1이고, 그 층의 요청은 지워집니다.
4. **방향 규칙** — 진행 방향에 요청이 남아 있으면 그 방향으로 계속 이동합니다. 진행 방향에 요청이 없고 반대 방향에 요청이 있으면 방향을 바꿉니다.
5. **대기** — 저장된 요청이 없으면 현재 층에서 문을 닫고 대기합니다.

---

## 4. 핵심 연산과 클럭 수

### 4.1 핵심 반복 연산

- 한 층을 이동하는 데 **3클럭**이 소요됩니다.
- **타이머 1개**를 층 사이 이동과 문 열림에 함께 사용하십시오. 이동용 타이머와 문 열림용 타이머를 따로 두는 구현은 인정하지 않습니다.
- 한 층 이동을 마칠 때마다 도착한 층의 요청과 진행 방향의 요청을 확인합니다. 더 이동할 요청이 있으면 다음 층 이동을 반복합니다.
- 반복의 종료는 데이터패스의 상태 신호(타이머의 0 검출, 현재 층 요청의 유무, 진행 방향 요청의 유무)로 판단합니다.

### 4.2 정확한 클럭 수

| 동작 | 요구 |
|------|------|
| 멈추지 않고 n층 이동 | `MOVE`가 **정확히 3n클럭 동안 연속으로** 1 |
| 문 열림 | `DOOR`가 **정확히 4클럭 동안 연속으로** 1 |
| 이동과 문 열림 | `MOVE`와 `DOOR`가 같은 클럭에 함께 1이 되지 않음 |

- 지나가는 층에서 `MOVE`가 0이 되는 클럭이 있으면 「연속」 요구를 충족하지 못합니다. 예: 1층에서 4층까지 멈추지 않고 이동하면 `MOVE`는 9클럭 동안 연속으로 1입니다.

### 4.3 처리 방식의 정의

| 상황 | 처리 |
|------|------|
| 리셋 직후 | 1층, 진행 방향 위, 문 닫힘, 저장된 요청 없음 |
| 이동 중이나 문이 열린 동안 누른 다른 층의 버튼 | 저장하고, 이후의 판단에 반영 |
| 한 층 이동을 마치는 클럭보다 2클럭 이상 앞서 누른 그 층의 버튼 | 그 층에서 정지 |
| 문이 열린 동안 누른 현재 층의 버튼 | 무시. 문 열림 시간을 연장하지 않음 |
| 정지 중에 위와 아래의 요청이 함께 있음 | 마지막 진행 방향의 요청을 먼저 처리 |

- 요청이 저장되는 시점, `FLOOR` 표시가 바뀌는 시점은 설계자가 정하고 보고서 1절에 적으십시오.
- 요청을 누른 뒤 이동을 시작하기까지의 클럭 수는 설계에 따라 다를 수 있습니다. 평가는 4.2의 요구와 처리 순서를 기준으로 합니다.

## 5. 지정 시나리오

- 클럭 번호는 리셋을 해제한 뒤의 첫 클럭을 1번으로 합니다.
- 입력열에 적지 않은 클럭에서 버튼은 모두 0입니다.
- 시나리오마다 리셋 직후의 상태에서 시작하십시오.

| # | 종류 | 입력열 | 추적할 클럭 | 확인 사항 |
|:--:|------|------|:--:|------|
| 1 | 정상 동작 1 | `B3` = 클럭 2\~3 | 1\~20 | 3층까지 `MOVE` 6클럭 연속<br>3층에서 `DOOR` 4클럭<br>이후 대기 |
| 2 | 정상 동작 2 | `B4` = 클럭 2\~3<br>`B2` = 클럭 20\~21 | 1\~36 | 4층까지 `MOVE` 9클럭 연속<br>4층에서 방향 전환<br>2층까지 `MOVE` 6클럭 연속 |
| 3 | 길게 누름 | `B2` = 클럭 2\~21 | 1\~26 | 2층에서 `DOOR`가 한 번만 4클럭<br>문이 닫힌 뒤 다시 열리지 않음 |
| 4 | 동시 입력 | `B3` = 클럭 2\~3<br>`B1`과 `B4` = 클럭 16\~17 | 1\~44 | 3층에 정지한 상태에서 위와 아래 요청이 함께 주어짐<br>4층을 먼저 처리<br>이어서 1층까지 `MOVE` 9클럭 연속 |
| 5 | 처리 중 입력 | `B4` = 클럭 2\~3<br>`B3` = 클럭 6\~7<br>`B3` = 클럭 11\~12 | 1\~28 | 이동 중에 누른 3층에 정지<br>3층 문이 열린 동안 누른 `B3`은 무시(문 4클럭, 다시 열리지 않음)<br>이어서 4층 처리 |

- 시나리오마다 공통 사양서 5.1의 형식으로 추적 표를 작성하고, Logisim 결과와 대조하십시오.
- 추적 표의 「레지스터와 카운터의 값」에는 저장된 요청, 현재 층, 진행 방향, 타이머 값을 포함하십시오.

---

## 6. 변형 질문

1. 문 열림을 4클럭에서 **6클럭**으로, 한 층 이동을 3클럭에서 **5클럭**으로 바꾸려면 설계의 어디를 어떻게 고쳐야 합니까. 고치지 않아도 되는 곳도 함께 적으십시오.
2. 문이 열린 동안 현재 층의 버튼을 누르면 **문 열림 4클럭을 다시 시작**하도록 바꾸려면 설계의 어디를 어떻게 고쳐야 합니까. 문이 열린 지 2번째 클럭에 버튼을 누르면 문은 모두 몇 클럭 동안 열립니까.

- 설계 절차, 입력 조건(한 번 누름의 한 번 처리), 리셋, 비정상 상태 추적, 제출물, 평가 기준은 [공통 사양서](프로젝트_공통_사양서.md)를 따릅니다.
