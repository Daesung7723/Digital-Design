# 컨트롤로직 설계 — 학기 프로젝트 주제별 사양서: 자판기

### 동전 2종, 상품 2종 자판기 제어기

> 이 문서는 학기 프로젝트 **자판기 주제**의 필수 기능, 핵심 연산, 지정 시나리오를 정한 사양서입니다.
>
> 설계 절차, 공통 요구 사항, 제출물, 평가 기준은 [공통 사양서](프로젝트_공통_사양서.md)에서 정합니다. 두 문서를 함께 확인하십시오.

---

## 1. 주제 개요

| 항목 | 내용 |
|------|------|
| 설계 대상 | 100원과 500원 동전을 받아 상품 2종을 판매하는 자판기 제어기 |
| 제어하는 동작 | 투입 금액을 누적해 상품을 내주고 잔돈을 반환 |
| 핵심 반복 연산 | 잔돈을 클럭마다 동전 1개씩 감산하며 반환(500원 먼저, 그다음 100원) |
| 클럭 수 요구 | 반환할 동전이 k개 = 반환 신호가 정확히 k클럭 연속, 바로 다음 클럭에 대기 상태 |

---

## 2. 입출력 정의

| 구분 | 신호 | 비트 | 의미 |
|------|------|:--:|------|
| 입력 | `C100`, `C500` | 각 1 | 100원, 500원 동전 투입 센서. 동전 1개가 투입되면 2클럭 이상 1 |
| 입력 | `A`, `B` | 각 1 | 상품 A, 상품 B의 선택 버튼. 누르는 동안 1 |
| 입력 | `CAN` | 1 | 취소 버튼. 누르는 동안 1 |
| 입력 | `RESET` | 1 | 리셋 |
| 출력 | `AMT` | 5 | 금액 표시. 100원 단위의 값(0\~31) |
| 출력 | `DISP_A`, `DISP_B` | 각 1 | 상품 A, 상품 B 배출. 1인 클럭에 상품 1개 배출 |
| 출력 | `RET500`, `RET100` | 각 1 | 500원, 100원 동전 반환. 1인 클럭마다 동전 1개 반환 |
| 출력 | `REJECT` | 1 | 거부. 받지 않은 동전이나 처리하지 않은 구매가 있으면 1 |

- 클럭 입력은 따로 둡니다.
- 금액은 100원 단위로 저장합니다. 예: 1,200원은 12입니다.
- `AMT`는 2진 표시와 16진 표시 가운데 어느 것을 사용해도 됩니다.

---

## 3. 기능 정의

1. **금액 누적** — 100원이나 500원 동전이 투입되면 금액에 더합니다. 금액의 상한은 3,100원입니다.
2. **상한 거부** — 더한 금액이 3,100원을 넘게 되는 동전은 받지 않습니다. 금액은 그대로 두고 `REJECT`를 1로 합니다.
3. **구매** — 상품 A는 700원, 상품 B는 1,200원입니다. 버튼을 누른 상품의 가격 이상의 금액이 있으면 금액에서 가격을 빼고 그 상품의 배출 신호(`DISP_A` 또는 `DISP_B`)를 1로 합니다. 이어서 남은 금액을 모두 반환합니다.
4. **금액 부족 거부** — 금액이 가격 미만이면 구매를 처리하지 않습니다. 금액은 그대로 두고 `REJECT`를 1로 합니다.
5. **취소** — 취소 버튼을 누르면 투입 금액을 모두 반환합니다.
6. **잔돈 반환** — 500원 동전을 먼저 반환하고, 그다음 100원 동전을 반환합니다. 한 클럭에 동전 1개를 반환하며, 반환하는 클럭에 그 동전의 반환 신호(`RET500` 또는 `RET100`)가 1입니다.
7. **대기** — 처리할 입력이 없으면 금액을 유지하고 대기합니다.

---

## 4. 핵심 연산과 클럭 수

### 4.1 핵심 반복 연산

- 잔돈은 한 클럭에 동전 1개씩 반환합니다. 남은 금액이 500원 이상이면 500원을 빼고 `RET500`을 1로 합니다. 500원 미만이면 100원을 빼고 `RET100`을 1로 합니다. 남은 금액이 0원이 될 때까지 반복합니다.
- 500원 감산과 100원 감산에 **감산기 1개**를 함께 사용하십시오. 500원용 감산기와 100원용 감산기를 따로 두는 구현, 반환할 동전의 개수를 조합회로로 한 번에 계산하는 구현은 인정하지 않습니다.
- 동전을 더하는 연산과 가격을 빼는 연산에 같은 부품을 함께 사용할지는 설계자가 정합니다.
- 반복의 종료는 데이터패스의 상태 신호(남은 금액과 500원의 비교, 마지막 동전의 검출)로 판단합니다.

### 4.2 정확한 클럭 수

| 동작 | 요구 |
|------|------|
| 동전 k개 반환 | `RET500`과 `RET100` 가운데 하나가 **정확히 k클럭 동안 연속으로** 1 |
| 반환 순서 | `RET500`이 먼저 모두 나온 뒤에 `RET100`이 나옴. 두 신호가 같은 클럭에 함께 1이 되지 않음 |
| 반환 종료 | 마지막 반환 신호가 1인 클럭의 **바로 다음 클럭**에 대기 상태 |
| 배출과 거부 | `DISP_A`, `DISP_B`, `REJECT`는 한 번에 정확히 1클럭 동안 1 |
| 구매 뒤의 반환 | 배출 신호가 1인 클럭의 바로 다음 클럭에 첫 반환 신호 |

- 반환 신호 사이에 반환 신호가 모두 0인 클럭이 있으면 「연속」 요구를 충족하지 못합니다. 예: 1,300원을 반환하면 `RET500` 2클럭과 `RET100` 3클럭이 5클럭 동안 연속으로 나오고, 6번째 클럭은 대기 상태입니다.
- 남은 금액이 0원인지 확인만 하는 클럭을 두면 「바로 다음 클럭에 대기 상태」 요구를 충족하지 못합니다.

### 4.3 처리 방식의 정의

| 상황 | 처리 |
|------|------|
| 리셋 직후 | 금액 0원, 대기 상태, 출력 모두 0 |
| 금액 3,000원에서 투입된 100원 | 받음. 금액 3,100원 |
| 금액과 가격이 같은 구매 | 배출 신호 1클럭. 반환 신호 없이 다음 클럭에 대기 상태 |
| 금액 0원에서 누른 취소 버튼 | 반환 신호와 `REJECT` 없이 대기 상태 유지 |
| 같은 클럭에 주어진 두 입력 | `C500`, `C100`, `CAN`, `A`, `B`의 순서로 하나씩 모두 처리. 뒤로 밀린 입력을 버리지 않음 |
| 반환 중에 투입된 동전, 반환 중에 누른 버튼 | 반환을 멈추거나 늘리지 않음. 반환이 완료된 뒤에 처리. 버리지 않음 |
| 받지 않은 동전 | `REJECT`만 1클럭. `RET500`과 `RET100`은 내지 않음 |

- 입력이 처리되는 시점은 설계자가 정하고 보고서 1절에 적으십시오.
- 입력이 주어진 뒤 처리되기까지의 클럭 수는 설계에 따라 다를 수 있습니다. 평가는 4.2의 요구와 처리 결과(금액, 신호의 순서와 클럭 수)를 기준으로 합니다.
- 같은 입력은 앞서 주어진 입력이 처리된 뒤에 다시 주어진다고 가정합니다. 예: 반환 중에 같은 종류의 동전이 2개 이상 투입되는 경우는 다루지 않습니다.

## 5. 지정 시나리오

- 클럭 번호는 리셋을 해제한 뒤의 첫 클럭을 1번으로 합니다.
- 입력열에 적지 않은 클럭에서 입력은 모두 0입니다.
- 시나리오마다 리셋 직후의 상태에서 시작하십시오.

| # | 종류 | 입력열 | 추적할 클럭 | 확인 사항 |
|:--:|------|------|:--:|------|
| 1 | 정상 동작 1 | `C500` = 클럭 2\~3<br>`C100` = 클럭 6\~7<br>`A` = 클럭 10\~11<br>`C100` = 클럭 14\~15<br>`A` = 클럭 18\~19<br>`CAN` = 클럭 22\~23 | 1\~26 | 600원에서 누른 `A`는 `REJECT` 1클럭, 금액 유지<br>700원에서 누른 `A`는 `DISP_A` 1클럭, 반환 신호 없음<br>0원에서 누른 `CAN`은 신호 없음 |
| 2 | 정상 동작 2 | `C500` = 클럭 2\~3, 6\~7, 10\~11, 14\~15, 18\~19, 22\~23, 26\~27<br>`C100` = 클럭 30\~31, 34\~35<br>`B` = 클럭 38\~39 | 1\~48 | 7번째 `C500`은 `REJECT` 1클럭, 금액 3,000원 유지<br>첫 번째 `C100`으로 금액 3,100원<br>두 번째 `C100`은 `REJECT` 1클럭<br>`DISP_B` 1클럭에 이어 `RET500` 3클럭과 `RET100` 4클럭이 7클럭 연속<br>다음 클럭에 대기 상태 |
| 3 | 길게 누름 | `C500` = 클럭 2\~9<br>`C500` = 클럭 12\~13<br>`A` = 클럭 16\~29 | 1\~32 | 길게 유지된 `C500`은 한 번만 누적, 금액 1,000원<br>`DISP_A`가 한 번만 1클럭<br>`RET100` 3클럭 연속<br>반환이 완료된 뒤 `A`가 1인 동안 `DISP_A`와 `REJECT`가 다시 나오지 않음 |
| 4 | 동시 입력 | `C500`과 `C100` = 클럭 2\~3<br>`C500`과 `A` = 클럭 6\~7<br>`CAN` = 클럭 14\~15 | 1\~20 | 두 동전이 모두 누적되어 금액 600원<br>`C500`과 `A`는 동전을 먼저 처리<br>1,100원에서 `DISP_A` 1클럭, `RET100` 4클럭 연속<br>반환 뒤 금액이 0원이므로 `CAN`은 신호 없음 |
| 5 | 처리 중 입력 | `C500` = 클럭 2\~3, 6\~7, 10\~11, 14\~15<br>`A` = 클럭 18\~19<br>`C100` = 클럭 21\~22<br>`CAN` = 클럭 28\~29 | 1\~32 | 2,000원에서 `DISP_A` 1클럭, `RET500` 2클럭과 `RET100` 3클럭이 5클럭 연속<br>반환 중에 투입된 `C100`은 반환을 멈추거나 늘리지 않음<br>반환이 완료된 뒤 금액 100원으로 누적<br>`CAN`으로 `RET100` 1클럭, 다음 클럭에 대기 상태 |

- 시나리오마다 공통 사양서 5.1의 형식으로 추적 표를 작성하고, Logisim 결과와 대조하십시오.
- 추적 표의 「레지스터와 카운터의 값」에는 금액, 입력을 저장한 플립플롭의 값을 포함하십시오.
- 시나리오 4는 4.3에서 정한 처리 순서(`C500`, `C100`, `CAN`, `A`, `B`)를 따라야 합니다.

## 6. 변형 질문

1. 상품 B의 가격을 1,200원에서 **1,300원**으로 바꾸려면 설계의 어디를 어떻게 고쳐야 합니까. 고치지 않아도 되는 곳도 함께 적으십시오. 금액이 2,000원일 때 B를 구매하면 `RET500`과 `RET100`은 각각 몇 클럭 동안 1입니까.
2. 반환 신호와 다음 반환 신호 사이에 **두 반환 신호가 모두 0인 클럭 1개**를 두도록 바꾸려면 설계의 어디를 어떻게 고쳐야 합니까. 마지막 반환 신호의 바로 다음 클럭은 그대로 대기 상태로 합니다. 잔돈이 800원이면 첫 반환 신호가 나온 클럭부터 마지막 반환 신호가 나온 클럭까지 모두 몇 클럭입니까.

## 7. 유의 사항

- 설계 절차, 입력 조건(한 번 누름의 한 번 처리), 리셋, 비정상 상태 추적, 제출물, 평가 기준은 [공통 사양서](프로젝트_공통_사양서.md)를 따릅니다.
- 가격, 금액의 상한, 클럭 수, 처리 방식은 이 문서의 값을 그대로 사용하십시오. 임의로 바꾸면 지정 시나리오로 검증할 수 없습니다.
