## 7. ASMD 설계 예제

### 학습목표

- ASMD 설계 예제의 Datapath 구성 요소와 Control Unit 조건을 파악할 수 있다.
- ASMD Chart를 작성하는 3단계 절차를 실제 예제에 적용할 수 있다.

---

### 7.1 설계 사양

> **Datapath Unit 구성:**
> - JK 플립플롭 2개: **E**, **F**
> - 4-bit 2진 카운터: **A[3:0]** (A3이 MSB)
>
> **동작 조건:**
> - **Start** 신호로 카운터 A와 FF F가 클리어되면서 동작 시작
> - 매 클럭 펄스마다 A가 1씩 증가
> - **Reset_bar = 0**일 때 전체 초기화
>
> **Control Unit 조건:**
> - **(A2 = 0)**: E = 0, 카운트 계속
> - **(A2 = 1)**: E = 1 처리 후
>   - A3 = 0이면 카운트 계속
>   - A3 = 1이면 다음 클럭에서 F = 1, 카운트 중지
> - **Start = 0**: 초기 상태에서 정지
> - **Start = 1**: 시스템 동작

---

### 7.2 ASMD 설계 Step 1 — Controller ASM Chart 작성

Controller 관점에서 상태 흐름만 먼저 정의합니다.

**상태 정의:**

| 상태 | 이름 | 의미 |
|:---:|:---:|:---:|
| **S\_IDLE** | 00 | 대기 상태 (Start = 0이면 유지) |
| **S\_COUNT** | 01 | 카운트 진행 중 (A2 = 0) |
| **S\_CHECK** | 10 | A2 = 1, E 처리 후 A3 확인 |
| **S\_STOP** | 11 | F = 1, 카운트 중지 |

**상태 천이 흐름:**

```
[S_IDLE]
    │
    ◇ Start = 1? ◇
   0↓              ↓1
[S_IDLE]       [S_COUNT]
                   │
               ◇ A2 = 1? ◇
              0↓           ↓1
          [S_COUNT]    [S_CHECK]
                           │
                       ◇ A3 = 1? ◇
                      0↓           ↓1
                  [S_COUNT]     [S_STOP]
                                    │
                                [S_STOP]
                                (F=1, 중지)
```

---

### 7.3 ASMD 설계 Step 2 — Datapath 연산 주석 추가

각 상태 천이 시 수행되는 레지스터 연산을 천이 경로에 추가합니다.

| 천이 경로 | 레지스터 연산 |
|---|---|
| S_IDLE → S_COUNT (Start=1) | $A \leftarrow 0$, $F \leftarrow 0$ (클리어 후 시작) |
| S_COUNT 유지 (A2=0) | $A \leftarrow A + 1$, $E \leftarrow 0$ |
| S_COUNT → S_CHECK (A2=1) | $A \leftarrow A + 1$, $E \leftarrow 1$ |
| S_CHECK → S_COUNT (A3=0) | $A \leftarrow A + 1$ |
| S_CHECK → S_STOP (A3=1) | $F \leftarrow 1$, 카운트 중지 |
| S_STOP 유지 | 유지 |

---

### 7.4 ASMD 설계 Step 3 — 제어 신호 명시

Controller에서 생성하는 제어 신호를 명시하여 ASMD Chart를 완성합니다.

| 제어 신호 | 동작 | 활성 조건 |
|---|---|---|
| **Clr_A** | 카운터 A 클리어 | S_IDLE → S_COUNT 천이 시 |
| **Clr_F** | FF F 클리어 | S_IDLE → S_COUNT 천이 시 |
| **Incr_A** | 카운터 A 증가 | S_COUNT, S_CHECK 활성 상태 |
| **Set_E** | E = 1 | A2 = 1 조건 충족 시 |
| **Clr_E** | E = 0 | A2 = 0 조건 충족 시 |
| **Set_F** | F = 1 | S_CHECK → S_STOP 천이 시 |

---

> [!note]- 정답 보기

## 8. ASIC과 Top-Down 설계 방법론

### 학습목표

- ASIC의 정의와 등장 배경을 설명할 수 있다.
- HDL과 Logic Synthesis의 역할을 이해한다.
- Top-Down 설계 계층에서 RTL 수준의 의미를 설명할 수 있다.

---

### 8.1 ASIC이란?

**ASIC(Application Specific IC)** 은 **특정 목적을 위해 설계된 IC** 입니다.

**ASIC 등장 배경:**

- 고성능 설계 도구의 발전
- 회로 집적도(Integration Density)의 증가
- 결과적으로 **하나의 칩에 전체 시스템을 직접 구현 가능** (System-on-Chip, SoC)

**설계 복잡도의 증가:**

$$\text{집적도} \uparrow \Rightarrow \text{설계 문제 복잡도 기하급수적 증가}$$

이 복잡도를 해결하기 위해 두 가지 핵심 도구가 등장했습니다:

| 도구 | 역할 |
|---|---|
| **HDL** (Hardware Description Language) | 하드웨어를 텍스트 코드로 추상화하여 기술 |
| **Logic Synthesis System** | HDL(RTL 코드)을 자동으로 Gate Level 회로로 변환 |

---

### 8.2 RTL 설계 수준의 의미

HDL의 등장으로 **설계 수준이 높아졌습니다**:

| 수준 전환 | 이전 | 이후 |
|---|---|---|
| 설계 추상화 수준 | Layout, Gate 수준 | **RTL 수준 이상** |
| 합성 방법 | 수동 게이트 연결 | **Logic Synthesis** (자동 합성) |
| 배치/배선 | 수동 | **Placement & Routing** (자동화) |

> 💡 현재 FPGA/ASIC 설계자들은 대부분  
> **Verilog 또는 VHDL로 RTL 수준 코드를 작성**하고,  
> 합성 툴이 자동으로 Gate Level 회로와 Layout을 생성합니다.  
> 이것이 현대 디지털 설계의 표준 플로우입니다 [file:25].

---

### 8.3 복습문제

#### 문제 (1)

HDL과 Logic Synthesis System이 각각 디지털 설계에서 어떤 역할을 하는지 설명하라.

> [!note]- 정답 보기
>
> - **HDL**: 하드웨어의 동작과 구조를 텍스트 코드(RTL 수준)로 기술하는 언어로,  
>   설계자가 게이트 하나하나를 연결하지 않고도 회로를 표현할 수 있게 합니다.
>
> - **Logic Synthesis System**: HDL로 작성된 RTL 코드를 입력받아  
>   실제 게이트 수준의 논리회로(Netlist)로 자동 변환해주는 설계 도구입니다.  
>   이 덕분에 설계자는 RTL 추상화 수준에서 작업하고,  
>   Gate Level 변환은 도구에 위임할 수 있습니다 [file:25].

## 9. 순차 2진 곱셈기 설계

### 학습목표

- 순차 2진 곱셈기의 동작 알고리즘을 이해한다.
- Datapath를 구성하는 레지스터들의 역할을 설명할 수 있다.
- ASMD Chart를 기반으로 설계 절차 전 과정을 추적할 수 있다.

---

### 9.1 설계 사양 및 알고리즘

**목적**: 부호 없는(Unsigned) 2진수 2개의 **곱셈 처리**

**알고리즘 원리 (이진 곱셈 = 반복 덧셈):**

$$B \times Q = \underbrace{B + B + B + \cdots + B}_{Q\text{회}}$$

하지만 단순 반복 덧셈이 아니라,  
피승수 $B$를 **시프트하면서 승수 $Q$의 각 비트에 따라 부분합을 누적**하는 방식을 사용합니다.

---

### 9.2 Datapath 구성 요소

슬라이드에서 확인된 Datapath 구성 요소 [file:25]:

| 레지스터 | 역할 | 초기값 |
|---|---|---|
| **B** (8-bit) | 피승수(Multiplicand) 저장 | 입력값 |
| **Q** (Shift Register, 16-bit 이상) | 승수(Multiplier) 저장, 매 단계 오른쪽 시프트 | 입력값 |
| **A** (Shift Register, 8-bit) | 부분곱(Partial Product) 누적 | 00000000 |
| **C** (1-bit) | 덧셈 올림(Carry) 저장 | 0 |
| **P** (4-bit Down Counter) | 남은 비트 수 추적 | 1000 (8) |

**제어 신호:**

| 신호 | 동작 |
|---|---|
| **Load_regs** | B, Q 레지스터에 피승수/승수 로드 |
| **Add_regs** | A = A + B (부분합 덧셈) |
| **Shift_regs** | C, A, Q를 오른쪽으로 1비트 시프트 |
| **Decr_P** | 카운터 P 1 감소 |

**Zero 신호:** P = 0이면 NOR 게이트 출력 Zero = 1 → **곱셈 완료 감지**

---

### 9.3 순차 2진 곱셈기 알고리즘

```
Step 1. Load_regs: B ← 피승수, Q ← 승수, A ← 0, P ← 8
          ↓
Step 2. Q = 1? (승수의 LSB 확인)
          ├─ Yes: Add_regs → A ← A + B (부분합 누적)
          └─ No:  아무 연산 없음
          ↓
Step 3. Shift_regs: C, A, Q 오른쪽 1비트 시프트
        (16-bit 결과가 C:A:Q 영역에 쌓임)
          ↓
Step 4. Decr_P: P ← P - 1
          ↓
Step 5. P = 0? (Zero = 1?)
          ├─ No: Step 2로 돌아가 반복
          └─ Yes: 곱셈 완료
                  최종 결과 = A:Q (상위 8비트: A, 하위 8비트: Q)
```

---

### 9.4 4-bit × 4-bit 곱셈 예제

$B = 1011_2 = 11_{10}$, $Q = 0110_2 = 6_{10}$, 기대 결과: $66_{10} = 01000010_2$

| 단계 | C | A | Q | P | 동작 |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 초기 | 0 | 0000 | 0110 | 4 | Load |
| 1 | 0 | 0000 | 0011 | 3 | Q[0]=0 → Shift |
| 2 | 0 | 1011 | 0001 | 2 | Q[0]=1 → Add, Shift |
| 3 | 0 | 1101 | 1000 | 1 | Q[0]=1 → Add, Shift |

> ⚠️ 위 예제는 4-bit 기준으로 단순화된 흐름입니다.  
> 실제 8-bit 곱셈기는 P=8부터 시작해 8회 반복합니다.  
> 슬라이드의 세부 그림과 함께 반드시 확인하세요 [file:25].

---

### 9.5 ASMD Chart 기반 설계 절차 요약

순차 2진 곱셈기의 전체 설계 절차:

```
1. 사양 결정 및 알고리즘 결정
      ↓
2. 시스템 구성 결정 (Controller / Datapath / 제어·데이터 라인)
      ↓
3. ASMD Chart 작성
      ↓
4. 상태 천이도 도출 (Controller 상태만)
      ↓
5. 상태 천이별 제어 상세 내용 정의
      ↓
6. 제어회로 상태표 작성
      ↓
7. 제어회로 설계 (Next-State Logic 도출)
      ↓
8. Datapath 설계 (레지스터, 가산기, 카운터 연결)
```

---

### 9.6 복습문제

#### 문제 (1)

순차 2진 곱셈기에서 카운터 P의 역할과 Zero 신호가 발생하는 조건을 설명하라.

> [!note]- 정답 보기
>
> **P의 역할**: 곱셈에서 처리해야 할 남은 비트 수를 추적하는 Down Counter입니다.  
> 매 단계(Add 또는 Shift 완료 후) 1씩 감소합니다.
>
> **Zero 신호**: P의 모든 비트가 0이 되면 NOR 게이트 출력이 1이 되어 Zero = 1을 생성합니다.  
> Controller는 Zero = 1을 확인하면 모든 비트를 처리했음을 알고 곱셈 연산을 종료합니다 [file:25].

## 10. 제어기 구현

### 학습목표

- Controller의 세 가지 내부 블록(Next-State Logic, State Register, State Decoder)의 역할을 설명할 수 있다.
- MUX를 이용한 Next-State Logic 구현 방식을 이해한다.
- 상태표를 기반으로 플립플롭 입력과 출력 신호를 결정할 수 있다.

---

### 10.1 Controller 내부 구조

모든 FSM 기반 Controller는 아래 세 블록으로 구성됩니다 [file:25]:

```
외부 입력 (Start, Zero, E, …)
         │
         ▼
┌─────────────────────────┐
│   Next-State Logic      │  ← 조합논리: 다음 상태 결정
│   (다음 상태 계산)       │
└────────────┬────────────┘
             │ D1 D0 (플립플롭 입력)
             ▼
┌─────────────────────────┐
│   State Register        │  ← 플립플롭: 현재 상태 저장
│   (현재 상태 저장)       │
└────────────┬────────────┘
             │ G1 G0 (현재 상태 출력)
             ▼
┌─────────────────────────┐
│   State Decoder         │  ← 조합논리: 제어 신호 생성
│   (출력 제어신호 생성)   │
└────────────┬────────────┘
             │ Ready, Incr_R2, Shift_left, Load_regs, …
             ▼
          Datapath Unit
```

---

### 10.2 각 블록의 역할

| 블록 | 유형 | 역할 |
|---|---|---|
| **Next-State Logic** | 조합논리 | 현재 상태 $G$와 외부 입력을 받아 다음 상태 $D$ 계산 |
| **State Register** | 순차논리 (D-FF) | 클럭 에지에서 다음 상태를 현재 상태로 저장 |
| **State Decoder** | 조합논리 | 현재 상태를 기반으로 Datapath에 내릴 제어 신호 생성 |

---

### 10.3 MUX를 이용한 Next-State Logic 구현

슬라이드에서 제시된 방식으로, **MUX를 이용해 Next-State Logic을 구현**합니다 [file:25].

**원리:**

- 각 상태($G1G0$)마다 가능한 다음 상태 후보들이 존재합니다.
- 외부 입력(Start, Zero, E 등)이 MUX의 선택 신호로 사용됩니다.
- MUX가 조건에 따라 올바른 다음 상태를 출력합니다.

**상태표 예시 (Set Bit Count 예제 기준)** [file:25]:

| 외부 입력 | 현재 상태 $G1G0$ | 다음 상태 $D1D0$ |
|:---:|:---:|:---:|
| Start = 0, X, X | 00 | 00 |
| Start = 1, X, X | 00 | 01 |
| X, Zero = 1, X | 01 | 00 |
| X, Zero = 0, X | 01 | 10 |
| X, X, X | 10 | 11 |
| X, X, E = 0 | 11 | 10 |
| X, X, E = 1 | 11 | 01 |

---

### 10.4 출력 신호 생성 (State Decoder)

State Decoder는 현재 상태에 따라 아래 출력 신호를 활성화합니다:

| 현재 상태 | 활성화되는 출력 신호 |
|:---:|:---:|
| 00 (IDLE) | 없음 (대기) |
| 01 | Ready = 1 |
| 10 | Incr_R2 = 1, Shift_left = 1 |
| 11 | Load_regs = 1 |

---

### 10.5 복습문제

#### 문제 (1)

FSM Controller의 세 가지 내부 블록을 나열하고,  
각 블록이 조합논리인지 순차논리인지 구분하여 설명하라.

> [!note]- 정답 보기
>
> | 블록 | 종류 | 이유 |
> |---|---|---|
> | Next-State Logic | **조합논리** | 입력(현재 상태 + 외부 입력)이 정해지면 즉시 출력(다음 상태)이 결정됨 |
> | State Register | **순차논리** | 클럭 에지에서만 상태가 갱신됨 (플립플롭 사용) |
> | State Decoder | **조합논리** | 현재 상태가 정해지면 즉시 출력 신호가 결정됨 |

---

#### 문제 (2)

MUX를 이용한 Next-State Logic에서, MUX의 선택(Select) 신호에 해당하는 것은 무엇인가?

> [!note]- 정답 보기
>
> **외부 입력 신호** (예: Start, Zero, E 등) 가 MUX의 Select 신호 역할을 합니다.  
> 각 외부 입력의 값에 따라 MUX가 다음 상태 후보들 중 하나를 선택하여 출력합니다 [file:25].

## 11. Register의 Set Bit Count 예제

### 학습목표

- Set Bit Count 예제의 동작 사양을 파악할 수 있다.
- ASMD Chart → 상태표 → Controller 구현의 흐름을 추적할 수 있다.

---

### 11.1 설계 사양

**목적**: 레지스터 R의 값에서 **비트 1의 개수(Set Bit Count)** 를 세는 회로

**Datapath 구성:**

| 요소 | 역할 |
|---|---|
| **R** (Shift Register) | 검사할 데이터 저장, 매 단계 왼쪽 시프트 |
| **R2** (카운터) | Set Bit(1인 비트) 개수 누적 |

**동작 조건:**

| 신호 | 조건 | 동작 |
|---|---|---|
| **Start = 0** | 초기 상태 | 정지 대기 |
| **Start = 1** | 동작 시작 | R 로드 후 반복 시작 |
| **Zero = 1** | R 전체가 0 | 카운팅 완료 → 정지 |
| **E = R[MSB]** | 현재 MSB 값 | E = 1이면 R2 증가, 항상 R 시프트 |

---

### 11.2 동작 알고리즘

```
Step 1. Start = 1 확인 → R 로드, R2 ← 0
          ↓
Step 2. Zero = 1? (R의 모든 비트가 0인가?)
          ├─ Yes: 종료 (R2에 Set Bit Count 저장됨)
          └─ No:
               ↓
Step 3. E = R[MSB] 확인
          ├─ E = 1: R2 ← R2 + 1 (Incr_R2)
          └─ E = 0: R2 유지
               ↓
Step 4. Shift_left: R ← shl(R) (왼쪽 시프트)
          ↓
Step 5. Step 2로 돌아가 반복
```

---

### 11.3 상태 정의 및 제어 신호

**Controller 상태:**

| 상태 코드 | 의미 | 활성 제어 신호 |
|:---:|:---:|:---:|
| **00** | IDLE (Start 대기) | Ready = 1 |
| **01** | Load 후 Zero 검사 | Load_regs = 1 |
| **10** | E 값에 따라 R2 증가 + 시프트 | Incr_R2 (E=1), Shift_left |
| **11** | 내부 천이 상태 | — |

**상태 천이 요약:**

$$00 \xrightarrow{Start=1} 01 \xrightarrow{Zero=0} 10 \xrightarrow{} 11 \xrightarrow{E=1} 01$$

$$01 \xrightarrow{Zero=1} 00 \quad (\text{완료})$$

---

### 11.4 예제 트레이스

**R = 1011\_0100 (8-bit)** 기준 (Set Bit = 4개):

| 단계 | R (시프트 전) | R[MSB] = E | R2 | 동작 |
|:---:|:---:|:---:|:---:|:---:|
| 초기 | 10110100 | 1 | 0 | Load |
| 1 | 10110100 | 1 | 1 | Incr_R2, Shift |
| 2 | 01101000 | 0 | 1 | Shift만 |
| 3 | 11010000 | 1 | 2 | Incr_R2, Shift |
| 4 | 10100000 | 1 | 3 | Incr_R2, Shift |
| 5 | 01000000 | 0 | 3 | Shift만 |
| 6 | 10000000 | 1 | 4 | Incr_R2, Shift |
| 7 | 00000000 | 0 | 4 | Zero=1 → 종료 |

최종 R2 = **4** ✓ ($1011\_0100$에서 1이 4개)

### 11.5 복습문제

#### 문제 (1)

Set Bit Count 회로에서 Zero 신호의 역할을 설명하고,  
Zero = 1이 되는 조건을 논리식으로 나타내라.

> [!note]- 정답 보기
>
> **역할**: Zero 신호는 레지스터 R의 모든 비트가 0이 되었는지 감지합니다.  
> Zero = 1이 되면 Controller가 카운팅 완료로 판단하고 IDLE 상태로 돌아갑니다.
>
> **논리식** ($n$-bit 레지스터 R 기준):
>
> $$\text{Zero} = \overline{R[n-1] + R[n-2] + \cdots + R[1] + R[0]}$$
>
> 즉, R의 모든 비트에 대한 NOR 연산입니다.  
> 모든 비트가 0일 때만 출력이 1이 됩니다 [file:25].
